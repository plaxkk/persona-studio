# 灵感到定稿

“写推文”管理创作过程，“内容库”管理完成后的内容与发布操作。

1. 在写推文记下工作片段、疑问或半句话，选择“仅暂存灵感”或“保存并开始创作”。保存本身不调用模型。
2. 打开灵感，点击“帮我找三个角度”，或写下自己的问题继续脑暴。每份灵感有独立对话，使用当前选定的写作引擎与人格。
3. 选择角度、补充事实后点击“生成候选稿”。继续提出修改意见，选择“继续脑暴”讨论，或“按讨论修改候选稿”更新正文；也可直接手动编辑正文。
4. 正文和灵感编辑后自动保存，导航离开前也会保存。生成期间可以离开再回来；失败或停止不覆盖已有候选稿，“恢复本轮要求”可重新编辑后重试。
5. 点击“确认定稿”，检查后“保存为最终稿”。只有此时才创建正式草稿，保留原灵感与全部对话，不自动发布到 X。
6. 点击“到内容库查看定稿”处理编辑、复制、手动发布和归档。创作页显示最新正文，内容库可以回看关联的灵感与对话。旧草稿仍保留在内容库。
7. 在创作页右侧“配图与视频”添加素材：图片最多 4 个，视频最多 1 个（含视频时总数仍为 4）。可以查看预览、下载或删除。素材只是发布时的参考，保存在本机，**不会自动发到 X**；正文定稿后仍可继续添加或删除。

## 数据与并发

- `creations` 保存灵感、候选稿、阶段、版本、当前任务和最终草稿关联；迁移自动创建表，不修改既有草稿。
- 会话使用 `creation:<id>` 独立频道，不混入人格试聊。请求含原始灵感、当前候选稿、近期对话及较早的对话摘录。
- 新一轮在事务中检查版本并预留任务，阻止同一记录并行生成。生成期间禁止修改正文；停止后可继续编辑。
- 模型结果提交再次检查取消状态和记录版本。失败不会覆盖候选稿；重复定稿返回原来的草稿 ID。
- 创作阶段的“已定稿”与发布状态分开。发布状态沿用现有人工确认流程，不代表 X 平台验证。
- `creation_media` 记录附件（文件名、类型、字节数、sha256、本机路径），在定稿时关联到草稿；定稿后新加的附件也归入同一份草稿。
- 附件按 384 KB 分片传输：本机后端拒绝超过 1.2 MB 的请求体，本机桥只接受 950 KB 以内的 WebSocket 帧，一张手机照片就会顶到上限，短视频更是放不下。上传与读取都逐片进行，服务端按客户端给出的 sha256 校验拼装结果。
- 上传过程把元数据与字节写在 `.local/state/media/<创作 id>/` 下，`complete` 成功后才写入数据库行；中断的半个上传不会留下一条“看起来能用”的附件。残留的分片 24 小时后自动清理。
- 在线面板需要连接助手 1.3.5，附件功能需要 **1.3.14**；浏览器扩展和本机后端各有一份限定路由白名单，新增路由必须同时改 `browser-extension/desktop.js` 与 `studio/desktop.py`。
- 预览用 `blob:` 对象地址交给 `<img>` / `<video>`，因此内容安全策略必须放行：`img-src` 与 `media-src` 都含 `blob:`，而 `script-src` 刻意不含——附件永远不能变成可执行内容。这份策略同样**写了两处**（`studio/api.py::CONTENT_SECURITY_POLICY` 与 `vercel.json` 的响应头），浏览器两边都执行，只改一处会让另一个来源上的预览静默失效；`tests/test_content_security_policy.py` 会在两份漂移时报错。

## 验证

```sh
.venv/bin/python -m pytest tests/test_creations.py tests/test_creation_media.py -q
node --test tests/extension_upgrade.test.mjs
npm --prefix assets/web-admin run build
.venv/bin/python tests/creation_browser.py
npm --prefix assets/web-admin run build:desktop
PYTHONPATH=. .venv/bin/python tests/desktop_browser_e2e.py
```

浏览器验收使用临时数据库和模拟引擎，覆盖暂存、重新打开、多轮上下文、手改、失败重试、刷新恢复、显式定稿、内容库关联与手机布局。它不验证真实供应商的生成质量，也不发布到 X。

附件的隔离测试用伪造的小分片驱动完整的三步握手（声明、分片、完成），覆盖校验失败、分片乱序、类型与数量上限、中断残留与删除；`CHUNK` 在测试里被调小，以免在测试文件中塞进 400 KB 的样本。

`.local/acceptance/media-attachments.py` 做真实环境验收，两半分开报告：本机接口按 `media.ts` 的分片流程上传 1.4 MB 真实 PNG 与 602 KB 真实 H.264 视频（都可解码，不是随机字节改扩展名），逐字节比对落盘与读回；真实面板则经 CDP 挂独立调试 Chrome，走上传、预览、下载、删除，用下载文件与原图逐字节相同来证明分片重组完整。它只读渲染结果，验收完删掉自己签发的会话行。
