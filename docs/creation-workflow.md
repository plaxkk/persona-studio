# 灵感到定稿

“写推文”管理创作过程，“内容库”管理完成后的内容与发布操作。

1. 在写推文记下工作片段、疑问或半句话，选择“仅暂存灵感”或“保存并开始创作”。保存本身不调用模型。
2. 打开灵感，点击“帮我找三个角度”，或写下自己的问题继续脑暴。每份灵感有独立对话，使用当前选定的写作引擎与人格。
3. 选择角度、补充事实后点击“生成候选稿”。继续提出修改意见，选择“继续脑暴”讨论，或“按讨论修改候选稿”更新正文；也可直接手动编辑正文。
4. 正文和灵感编辑后自动保存，导航离开前也会保存。生成期间可以离开再回来；失败或停止不覆盖已有候选稿，“恢复本轮要求”可重新编辑后重试。
5. 点击“确认定稿”，检查后“保存为最终稿”。只有此时才创建正式草稿，保留原灵感与全部对话，不自动发布到 X。
6. 点击“到内容库查看定稿”处理编辑、复制、手动发布和归档。创作页显示最新正文，内容库可以回看关联的灵感与对话。旧草稿仍保留在内容库。

## 数据与并发

- `creations` 保存灵感、候选稿、阶段、版本、当前任务和最终草稿关联；迁移自动创建表，不修改既有草稿。
- 会话使用 `creation:<id>` 独立频道，不混入人格试聊。请求含原始灵感、当前候选稿、近期对话及较早的对话摘录。
- 新一轮在事务中检查版本并预留任务，阻止同一记录并行生成。生成期间禁止修改正文；停止后可继续编辑。
- 模型结果提交再次检查取消状态和记录版本。失败不会覆盖候选稿；重复定稿返回原来的草稿 ID。
- 创作阶段的“已定稿”与发布状态分开。发布状态沿用现有人工确认流程，不代表 X 平台验证。
- 在线面板需要连接助手 1.3.4；浏览器扩展和本机后端均有限定路由白名单。

## 验证

```sh
.venv/bin/python -m pytest tests/test_creations.py -q
node --test tests/extension_upgrade.test.mjs
npm --prefix assets/web-admin run build
.venv/bin/python tests/creation_browser.py
npm --prefix assets/web-admin run build:desktop
PYTHONPATH=. .venv/bin/python tests/desktop_browser_e2e.py
```

浏览器验收使用临时数据库和模拟引擎，覆盖暂存、重新打开、多轮上下文、手改、失败重试、刷新恢复、显式定稿、内容库关联与手机布局。它不验证真实供应商的生成质量，也不发布到 X。
