# X 连接兼容修复（2026-09-23）

现象：保存用户手动提供的 cookies 后，验证账号显示“部分读取来源暂时不可用”。

根因与处理：

1. Twikit 2.3.3 期待旧的网页资源名称到 hash 映射，X 已使用数字 chunk ID 的两段映射；初始化在 `ClientTransaction.get_indices` 失败。新增 `studio/twikit_compat.py` 兼容新旧映射，失败时停止读取，不跳过认证。
2. X 会省略用户资料中的可选列表：`withheld_in_countries`、`pinned_tweet_ids_str`、`entities.description.urls`。旧 SDK 直接索引导致整页抛出 KeyError。只对这些可选列表补空值，不伪造身份、正文或其他用户资料。
3. 原 `Client.user()` 经过账户设置、按名称查询、按 ID 重复查询；旧设置接口间歇性 404。改用只读 `account/verify_credentials.json` 直接取得当前已认证账号 ID 与用户名，仍与用户填写的账号核对。返回到产品的身份不包含该接口的邮箱、电话等额外字段。
4. 区分客户端兼容、网络、超时、登录失效和限流错误，避免所有问题都显示成部分来源失败。

没有升级到未经验证的 fork，没有修改虚拟环境中第三方源码；兼容层随项目发布。XReader 对外仍只有读取能力。没有读取浏览器数据库、输出 cookies 或绕过认证挑战。

参考上游：[资源映射变化 PR #412](https://github.com/d60/twikit/pull/412)、[可选字段缺失 Issue #417](https://github.com/d60/twikit/issues/417)。
