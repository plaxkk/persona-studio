## 尚需用户信息才能完成的真实验收

- 管理员初始密码：由用户在工作室界面设置，代理未代设。
- 所选引擎的模型名称、兼容接口地址、API Key：供应商模型连通与实际写作质量尚未验证。
- X 用户名、`auth_token` / `ct0` 或 Cookie-Editor 导出：当前账号身份与六个读取来源已实测；认证挑战和账号限流仍仅做模拟验证。
- 可选 Telegram Bot Token 与 owner 数字 ID：实际收取 owner 消息和发送通知尚未实测。
- 正式人设与可用语料：当前迁移的是旧版合成人格与 12 条合成语料，不是已经完成的个人定制人设。

这些能力在生产界面保持“待配置 / 未连接”，不会被模拟测试标为已就绪。连接测试不自动恢复同步。没有真实 X 自动发布功能或需要授权开启的 live 模式。

## 部署范围及后续边界

当前验证平台为 macOS Intel、Python 3.13、Node 24；Linux systemd 用户服务安装路径已实现，但未在 Linux 主机实机验收。远程 HTTPS 的 API 安全行为有自动测试，真实域名、证书和反向代理仍属于未来远程部署工作。

会话保存完整消息，附带有界的早期对话摘录；目前没有额外收费的语义摘要任务。失败模型任务不会自动重试扣费；自动预算按已接受的任务计数，失败/取消也占用当日自动预算。浏览和生成总量是保守上限，不保证每天必然产生相同数量草稿。

## 浏览器连接助手（2026-09-23 新增）

Chrome Manifest V3 扩展，授权指定 loopback origin 后使用官方 cookies API，仅读取 x.com 的 auth_token / ct0。API 管理员会话与 CSRF 发起五分钟一次性配对；扩展直接传送，页面无 cookie 明文。验证失败、账号错配、取消、过期、注销与配置变化均不能覆盖原凭据。18 项新增后端测试通过，全套累计 64 项。

`PYTHONPATH=. .venv/bin/python tests/browser_extension_e2e.py` 在临时 Chromium 配置和临时数据库中验证扩展真正加载、首次授权、未登录引导、HttpOnly cookie 读取、登录后自动验证/填入用户名、重开面板自动连接、过期登录后自动续接（模拟登录同时更新两个必要 cookie）、停止自动连接、桌面/手机布局。浏览器真实运行，X 登录页及身份接口为模拟夹具；不代表用户日常 Chrome 已安装扩展或真实登录已验收。安装说明见 [连接助手](../browser-extension/README.md)。
